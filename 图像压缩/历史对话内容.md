## 四、四档方案详解

**第一档（必做·自研，拿原理分）—— 从零实现 JPEG 风格 DCT 编码器**
- 流程：RGB→YCbCr（可选 4:2:0 下采样）→ 8×8 分块 DCT → 量化（用 JPEG 标准量化表，质量因子 Q 可调）→ Zigzag 扫描 → RLE + 哈夫曼熵编码；解码走逆过程。
- 用 `numpy`/`scipy.fftpack.dct` 就能写，约 150–250 行，完全"可复现源码"，报告原理最好讲。
- 这是**必得分项**，无论后面做不做极致，这一档都该有，因为"算法设计与实现"是硬要求，直接调库会显得单薄。

**第二档（进阶，加对比面）—— 小波 + 低秩两条线**
- 小波：`pywt` 做 DWT 多级分解 + 阈值量化/SPIHT 或 EZW，代表 JPEG2000 思路。
- SVD 低秩：对每个块做奇异值分解，保留前 k 个奇异值，展示"秩-误差"关系（这条线数学漂亮、图表好画，很加分）。

**第三档（极致·成熟编码器）—— AVIF / BPG**
- 传统编码框架里率失真的第一梯队。AVIF 可用 `pillow-avif-plugin` 或 `imageio`（依赖 AV1 库），BPG 需调 `bpgenc` 二进制（HEVC 帧内）。
- 相对 JPEG 同等质量可省 ~40–50% 码率，作为"工业界最强"的对比基准非常好用。

**第四档（极致·学术天花板）—— 神经图像压缩（Learned Image Compression）**
- 用 Facebook 的 `compressai` 库加载预训练模型（`bmshj2018-factorized` → `cheng2020-anchor` → `elic`），这是当前率失真性能的 SOTA 梯队，相对 JPEG 可省 **55–65%** 码率。
- 需要 `torch`，24 张 768×512 图在 CPU 上也能跑（速度会慢些，GPU 更快），但代码量和环境依赖最大，是"冲满分级"的选择。

> **我的建议**：**第一档（自研 JPEG）做"主算法" + 第三/四档做"性能对比基准"**。这样既有自研算法拿原理分，又有极致方案拿性能对比分，报告里一张 RD 曲线（PSNR-bpp）把自研 JPEG 和 AVIF/神经压缩画在一起，"极致性能"就立起来了。

## 五、评价指标要算对（报告加分细节）

- **压缩率**：基准用 `768×512×3 字节`（原始像素量），不是 PNG 文件大小；也可统一换算成 **bpp = 压缩总比特 / 像素总数**，跨分辨率更好比。
- **PSNR**：`10·log10(255² / MSE)`，MSE 按 RGB 三通道求平均；**SSIM** 直接用 `skimage.metrics.structural_similarity`（multichannel 模式）。
- **时间**：`time.perf_counter` 测 encode / decode 各一次，跑多次取平均，报告里写"XX ms @ 768×512"。
- 输出三样东西：① 24 张图指标汇总表（含均值/最好/最差）② 典型图像的 RD 曲线 ③ 压缩前后可视化对比图（放大局部看块效应/振铃）。
