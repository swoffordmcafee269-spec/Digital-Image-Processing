# 部署文档 · 数字图像处理实习（极暗 RAW 图像增强）

> 本文档说明如何从零开始搭建环境、接入数据、训练、评估与推理，完整复现本项目结果。
> 项目主线为**路线 B：轻量残差 UNet 监督学习**，并附带路线 A（传统方法）用于对比。

---

## 一、项目简介

- **任务**：把极暗场景（0.001–0.0001 lux）的 RAW 图像增强为正常曝光的 sRGB 图像（低光增强 + 强去噪 + 曝光/色彩恢复）。
- **数据集**：SIED（See-in-the-Extremely-Dark，ICCV 2025，课程内也称 BIED），含两个子集：
  - `Sony_0.001`（0.001–0.01 lux，1000 对）
  - `Canon_0.0001`（0.0001–0.001 lux，1000 对，更暗约 10 倍）
- **评价指标**：PSNR / SSIM / LPIPS（全量 1000 张测试图）。
- **技术路线**：
  - 路线 A：传统基线（Gamma / CLAHE / Retinex / 直方图拉伸），用于对比。
  - 路线 B（主线）：监督式轻量残差 UNet，RAW 域直接学习 RAW→sRGB 映射。

## 二、环境要求

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows / Linux / macOS 均可（本工程在 Windows 下开发验证） |
| Python | ≥ 3.9（本项目实测 3.14） |
| GPU | NVIDIA 显卡，≥ 8 GB 显存（本项目实测 RTX 5060 Laptop 8GB） |
| CUDA | 见下方「关键提醒」 |
| 主要依赖 | PyTorch、torchvision、numpy、opencv-python、scikit-image、lpips、rawpy 等 |

### ⚠️ 关键提醒：显卡与 CUDA 版本

- 本项目实测显卡为 **RTX 5060 Laptop（Blackwell 架构，sm_120）**，属于较新架构，
  **必须安装 CUDA 版 PyTorch ≥ 2.7 且 index-url 用 cu128**，否则会装成 CPU 版或旧 CUDA 版导致 `cuda.is_available()` 为 False。
- 若你的显卡是较旧的 Ampere（30 系）或 Ada（40 系），可改用 `cu121` 等对应版本（见 PyTorch 官方安装页）。
- 确认命令：`nvidia-smi` 查看显卡型号与驱动支持的 CUDA 版本。

## 三、环境搭建

### 1. 安装依赖

```bash
pip install -r requirements.txt
```

### 2. 安装匹配 CUDA 版本的 PyTorch（重要）

`requirements.txt` 中 `torch>=2.0` 默认可能装成 CPU 版，需手动按 CUDA 版本重装：

```bash
# RTX 50 系（Blackwell，本项目实测）：用 cu128
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128

# 30 系 / 40 系：可用 cu121
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
```

### 3. 环境自检

```bash
python scripts/check_env.py
```

应看到 `CUDA 可用: True` 与你的 GPU 型号/显存。若为 False，检查驱动与 torch 版本是否匹配。

## 四、数据准备

### 1. 下载数据

下载 SIED（课程内称 BIED）数据集，按以下结构放入 `data/`：

```
data/
├── Sony/
│   └── Sony_0.001/
│       ├── 0.001/        # 低光 RAW（.raw，uint16，3840×2160）
│       └── gt/           # GT sRGB 参考图（.jpg）
└── Canon/
    └── Canon_0.0001/
        ├── 0.0001/       # 低光 RAW
        └── gt/           # GT sRGB
```

> `make_filelist.py` 会**递归扫描**子集目录并按文件名主干自动配对，因此不要求精确目录名。

### 2. 相机参数（务必确认）

| 参数 | Sony | Canon |
|---|---|---|
| 黑电平 black_level | 512 | 512 |
| 白电平 white_level | 16383 | 16383 |

> 两个子集参数一致（Canon 已实测确认）。若换用 `.arw/.cr2` 等格式，`rawpy` 会自动读取真实黑/白电平，无需手动设置。

### 3. 生成配对清单

```bash
python scripts/make_filelist.py                 # Sony（config.yaml 默认 dataset=Sony）
python scripts/make_filelist.py --dataset Canon # Canon
```

会在 `data/Sony/`、`data/Canon/` 下生成 `train.txt` / `val.txt` / `test.txt`（各 900/100/1000 对）。

## 五、运行步骤

### 第 1 步：训练

```bash
# Sony
python src/train.py

# Canon（使用独立配置与输出目录）
python src/train.py --config configs/config_canon.yaml
```

常用覆盖参数（显存不足时，多个 `--set` 需逐个写出）：

```bash
python src/train.py --set train.patch_size=256 --set train.batch_size=4
python src/train.py --set train.epochs=10          # 先小 epoch 验证流程
python src/train.py --set train.resume=outputs/checkpoints/last.pt   # 断点续训
```

训练产物：`outputs/checkpoints/best.pt`（最优）、`last.pt`（最新）、`outputs/logs/train_log.csv`。

### 第 2 步：全量评估

```bash
python src/evaluate.py                                # Sony
python src/evaluate.py --config configs/config_canon.yaml   # Canon
```

输出（以 Sony 为例，Canon 同理）：
- `outputs/results/Sony/results.csv`：逐张 PSNR/SSIM/LPIPS + 均值
- `outputs/results/Sony/baseline.csv`：传统基线（CLAHE）逐张指标
- `outputs/results/Sony/images/`：模型增强结果图（`eval.save_images=true` 时）

### 第 3 步：可视化对比图

```bash
python src/visualize.py                                # Sony
python src/visualize.py --config configs/config_canon.yaml
```

输出 `outputs/results/{Sony,Canon}/comparison.png`（输入|路线B|基线|GT 四联对比图）。

## 八、常见问题 / 故障排查

### 1. `CUDA 可用: False`
- 检查是否装成 CPU 版 torch：`pip show torch`，看版本后缀是否有 `+cu`。
- RTX 50 系务必用 cu128 安装（见第三节）。

### 2. 显存不足（OOM）
- 调小 `train.patch_size`（256）与 `train.batch_size`（4），或关闭 `train.amp`。
- 评估/推理本身是 batch=1，一般不会 OOM。

### 3. 增强结果偏色 / 过曝
- 检查黑电平/白电平是否设置正确（Sony/Canon 均为 512/16383）。

### 4. `对比图中文显示为方块`
- `visualize.py` 已内置 `Microsoft YaHei` 等中文字体；若仍乱码，确认系统装有中文字体。

### 5. 评估耗时较长
- 全量评估的瓶颈在 LPIPS（每张约 5–6 秒），1000 张约 1.5 小时，属正常。仅需出图时用 `export_images.py` 可提速约 4 倍。

### 6. `make_filelist.py` 报「未找到子集目录」或「没有匹配到配对」
- 确认数据已按第四节结构放入，且 `config.yaml` 中 `data.root`/`data.dataset` 正确。
- 确认 RAW 与 GT 文件名主干一致（如 `1.raw` ↔ `1.jpg`）。
