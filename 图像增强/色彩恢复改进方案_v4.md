# 色彩恢复改进方案 v4（基于官方 SIED 论文 + 本地实测验证）

> **纯方案设计文档**，撰写期间未修改任何原有文件与结果。
> 关系说明：本文档是 `色彩恢复路线评估_v3.md` 的**升级替代版**。v3 的核心判断「加色度损失必然掉 PSNR」经论文消融与本地实测复核后，**判定为偏保守、需修正**。
> 命名以 `_v4` 区分，与 `README.md`、`部署文档.md`、`Sony_v1_总结.md`、`Canon_总结.md`、`色彩恢复路线评估_v3.md` 相互独立。

## 零、先看结论

### v3 的三条判断需要修正

| # | v3 的判断 | v4 修正 | 依据 |
|---|---|---|---|
| 1 | 加色度损失必然掉 PSNR（−0.2~−0.6） | **不必然**。官方消融中颜色损失是**三项齐涨** | ICCV'25 SIED 消融表 |
| 2 | 颜色与 PSNR 是 trade-off | **方向正确时是互补**。色彩工作可前移到数据侧 | 本地实测 |
| 3 | 单加色度损失即可救颜色 | **不够**。纯 RGB 直方图 KL 对去饱和几乎无感 | 本地实测 |

### 核心思路转变

```
v3 思路：网络一边去噪一边学调色，再加损失约束   ← 两个任务打架
v4 思路：把色彩工作前移到数据处理，网络只专注亮度与去噪  ← 任务解耦
```

## 一、官方论文做了什么（可借鉴的部分）

### 1.1 关键组件

SIED（ICCV 2025）的核心方法包含：

1. **Color Consistency Loss（L_ccl）**：在 sRGB 特征域计算逐通道颜色直方图的 KL 散度，权重 λ=0.1
2. **AICM（自适应光照校正模块）**：在 latent 空间用卷积+自适应池化估计逐通道放大系数，不依赖 GT 曝光值
3. **两阶段训练**：Stage1 训 encoder/decoder+AICM，Stage2 训扩散模型

### 1.2 官方消融实验（决定性证据）

| 变体 | PSNR | SSIM | LPIPS |
|---|---|---|---|
| 无颜色一致性损失 | 24.53（−0.32） | 0.836（−0.013） | 0.389（+0.029） |
| **完整方法** | **24.85** | **0.849** | **0.360** |

**结论**：加上颜色损失后，PSNR、SSIM 同时上涨，LPIPS 明显下降——**三项指标全部改善**。这直接反驳了 v3「加颜色必然掉 PSNR」的判断。

其他消融：无 AICM 掉 1.62 dB，单阶段训练掉 1.89 dB。

### 1.3 官方方法在本项目不可直接复用的部分

| 官方组件 | 能否复用 | 原因 |
|---|---|---|
| L_ccl（颜色一致性损失） | ✅ 需改造后复用 | 只需 GT sRGB，无额外依赖 |
| AICM | ⚠️ 只能借结构 | 官方依赖 L_icl 的 Retinex 监督，需要 gt_raw |
| L_icl（Retinex 光照损失） | ❌ 不可复用 | **本项目数据只有 2000 个 RAW + 2000 个 JPG，无 gt_raw** |
| 两阶段训练 | ❌ 不建议 | 官方是为扩散模型解耦设计的；UNet 单阶段足够 |
| 扩散主干 | ❌ 不可行 | 8GB 显存 + 单次 1 小时预算不允许 |

**关键约束已核实**：`data/Sony/` 与 `data/Canon/` 下各只有 1000 个 `.raw` + 1000 个 `.jpg`，无 `gt_raw`/`long` 目录。

## 二、本地实测验证（本方案的事实基础）

### 2.1 色彩丢失的量化现状

| 指标 | GT | 模型输出 | 保留率 |
|---|---|---|---|
| HSV 饱和度 S 均值 | 75.05 | 17.54 | **23.4%** |
| Lab 色度模均值 | 16.53 | 3.11 | **18.8%** |

### 2.2 关键发现一：颜色对 PSNR 权重很低

| 对比 | PSNR |
|---|---|
| GT vs 模型输出 | 19.58 dB |
| **GT vs GT 完全灰度化** | **27.39 dB** |

把 GT 彻底去色，PSNR 仍有 27.39 dB。说明当前 PSNR 的瓶颈是**亮度、噪声、结构**，不是颜色。这是「改善颜色不一定牺牲指标」的理论基础。

### 2.3 关键发现二：盲目提饱和度会掉分

| 饱和度增益 | PSNR | 变化 |
|---|---|---|
| 1.0（现状） | 20.24 | — |
| 2.0 | 20.02 | −0.22 |
| 3.0 | 19.61 | −0.63 |

颜色必须**方向正确**才有正收益，盲目放大反而有害。

### 2.4 关键发现三：WB 增益的两种估计方法，Gray World 更稳

对 Canon 三张图对比两种白平衡增益估计：

| 图号 | GT 反推增益 (R, B) | Gray World 增益 (R, B) | 判断 |
|---|---|---|---|
| 798 | 2.65, 1.03 | 2.09, 0.91 | 接近，都可用 |
| 555 | 2.39, 1.13 | 2.17, 0.94 | 接近，都可用 |
| **904** | **4.00, 4.00（撞上限，失真）** | **2.10, 1.70（合理）** | **GT 反推失效** |

**904 失效原因（已诊断）**：该图 RAW 亮部 R/G=0.153、B/G=0.199，物理上极不平衡；同时 GT 有 **72.7% 像素过曝**（>0.98）。亮部关联性被噪声与过曝破坏，导致反推不可靠。

**结论：应优先采用 Gray World（只用 RAW，不依赖 GT），GT 反推仅作交叉校验。** 这是对 Plan 初稿方案的重要修正。

### 2.5 关键发现四：纯 L_ccl 对去饱和惩罚不足

在真实 GT 上测试 L_ccl（逐通道 RGB 直方图 KL）对不同扰动的敏感度：

| 扰动 | L_ccl 值 |
|---|---|
| 完全灰度 | 0.672 |
| **去饱和一半** | **−0.064 ~ 0.352** |
| 饱和度 ×1.5 | 1.976 |
| 饱和度 ×2.0 | 3.103 |
| 过曝 1.1× | 4.002 |

**判读**：L_ccl 对**曝光偏差**极敏感（4.002），但对**去饱和几乎无感**（−0.064）。原因是 3 通道边缘直方图把色度信息摊薄了。

**结论：照搬论文的 L_ccl 大概率救不回灰白，必须额外加专门的色度损失。** 这是与「直接复现论文」路线的最大分歧点。

### 3.1 L0：零训练探测（强烈建议先做，10 分钟）

**目的**：用最快速度回答「白平衡到底值多少」，决定后续是否值得投入训练时间。

**新增文件**：`scripts/probe_wb_v4.py`（新文件，不动现有代码）

**流程**：
1. 读 `data/{Sony,Canon}/test.txt` 前 20 对
2. 用 **Gray World** 估计每图 WB 增益（在中高亮区间统计，避开噪声底和过曝）
3. 增益裁剪到 [0.5, 4.0]
4. 施加到 packed RAW 的 R/B 通道
5. 做全局曝光对齐（RAW 与 GT 差 2~3 个数量级，必须对齐）
6. `simple_demosaic` → gamma 2.2 → 计算 PSNR/SSIM/LPIPS + 饱和度恢复率

**预期**：PSNR 约 Sony 13~16 / Canon 12~15（无去噪，仅验证色彩方向）；**饱和度恢复率 55%~80%**

**判据**：
- 饱和度恢复率 > 55% → WB 是主因，值得做 L1
- < 40% → 说明还有 gamma/CCM 等第二来源，需先补 L3 的 gamma 项

#### 改动 3：新增两个颜色损失

**文件**：`src/models/losses.py`（追加于 `PerceptualLoss` 之后）

```python
class ChromaLoss(nn.Module):
    """Lab 色度损失（本方案的色度主力）。

    L = |a*_pred − a*_gt| + |b*_pred − b*_gt|，按 GT 饱和度加权。
    加权是关键：平坦区域（天空、墙面）不惩罚，聚焦真正有色的区域。
    """
    # 权重 w = (sqrt(a_g²+b_g²)/128)^0.5，归一化后使用

class ColorConsistencyLoss(nn.Module):
    """改造版 L_ccl（论文原版 + 四项必要修正）。

    与论文的差异：
    1. 直方图先去通道均值再统计（剥离曝光/亮度分布，只留颜色分布）
    2. 通道间共享 bin 边界，边界取 GT 的 [min,max]（保证可比）
    3. 额外在 Lab a*/b* 通道算一份（实测证明纯 RGB 不够）
    4. tau 用 warmup（前期 1e-1 防抖，后期 1e-2 收紧）
    bins=64, tau=1e-2
    """
```

**实现要点（避免踩坑，来自实测）**：
- 软分箱用**扁平索引** `base + i0`，不要用二维广播（会撞 `index_put` 形状错误）
- 空 bin 必须 `clamp_min(1e-6)`，否则 `0·log0` 出 `nan`
- GT 直方图**先加 τ 再归一化**，否则 KL 有非零下界
- 梯度量级约 1e-7~3e-6，**λ 的合理范围是 0.5~20，不是论文的 0.1**（论文 0.1 对应扩散模型的残差尺度，不能照搬）

#### 改动 4：损失挂载

### 3.3 L2：完整版（推荐终点）

L2 补 L1 的三个缺口：

#### 缺口 1：网络缺少亮度自适应能力

**文件**：`src/models/unet.py`

新增 `SimpleAICM`，插在 `self.inc` 之后（第 77 行）：

```
输入 F (B,32,H,W)
  ├─ 1×1 conv → (B,16,H,W)
  ├─ 3×3 conv ×2 + LeakyReLU
  ├─ AdaptiveAvgPool2d(1) → 1×1 conv → Sigmoid → A ∈ (0,1)
  ├─ F_enhanced = F × (1 + α·A)     # α 可学习，初值 0.1
  └─ conv3x3(F_enhanced) + F        # 残差重建
```

参数增量约 **2.5k**，显存增量 < 5 MB，训练耗时增量 < 3%。

**与官方的差异**：官方用 AICM + L_icl（Retinex 监督）；本项目无 gt_raw，**改为软增益 `1+α·A` 防训练初期推爆特征，并用亮度统计损失替代 L_icl**。

#### 缺口 2：无 gt_raw → 用 GT 亮度统计替代

**文件**：`src/models/losses.py` 新增 `IllumStatLoss`

```python
L = Σ_{q∈{0.1,0.25,0.5,0.75,0.9}} | quantile_q(Y_pred) − quantile_q(Y_gt) |
```
权重 `lambda_illum = 0.05`。它只管亮度分布、不管色相，因此必须与 `ChromaLoss` 共存。

#### 缺口 3：用 PSNR 选模会选中最灰的模型

**文件**：`src/train.py`（第 132–160 行）

改为复合评分：

```python
val_score = val_psnr + 8.0*(val_chroma_ratio - 0.5) - 2.0*val_ssim_loss
```

验证集每 epoch 额外算 SSIM 与饱和度比。若预算紧，可每 5 epoch 完整验证一次。
`train_log.csv` 增加列 `val_ssim, val_sat_ratio, val_score`。

### 3.4 L3：部署版（可选，非必须）

只做一个组件：`GainEstimator`（解决「推理时没有 GT」）

```
输入: packed RAW 逐通道统计量 (4×3: p50,p95,p99.5) = 12 维
网络: MLP(12→32→2) → Sigmoid 缩放 → (g_R, g_B) ∈ [0.5, 4.0]
监督: 用 Gray World 算出的增益做 L1 回归
```

价值：让 `inference.py` 不依赖 GT，可真正部署。**它不负责涨指标**，别为它花训练预算。

## 五、能否达到「既要既要」

你的要求：**三个指标都要涨，同时颜色也要改善**。

### 判断：L2 有较高把握达到，L1 是保底

| 判断项 | L1 | L2 |
|---|---|---|
| PSNR 上涨 | ✅ 较有把握（+0.8~+2.2） | ✅ 更有把握（+1.3~+2.7） |
| SSIM 上涨 | ✅ 较有把握（+0.02~+0.05） | ✅ 更有把握（+0.03~+0.06） |
| LPIPS 下降 | ✅ 较有把握（−0.05~−0.12） | ✅ 更有把握（−0.08~−0.15） |
| 颜色改善 | ✅ 70~88% | ✅ 78~92% |

### 相比 v3 为什么更有把握

| v3 的逻辑 | v4 的逻辑 |
|---|---|
| 加色度损失 → 与 L1 冲突 → PSNR 必掉 | 前处理让目标颜色「几乎免费」→ 损失只需兜底 → 冲突很小 |
| 忽略了官方 L_ccl 的正收益证据 | L_ccl 在官方消融中是三项齐涨，且本项目色偏更严重，收益应更大 |
| 用 PSNR 单指标选模 | 复合评分选模，避免选中最灰的模型 |
| 单加 L_ccl 就以为够 | 实测证明 L_ccl 管曝光不管色度，必须补 ChromaLoss |

### 仍存在的风险（必须诚实说）

1. **数值是推算**。真实结果取决于超参调优，可能落在区间外。
2. **`chroma_weight` 调不好会出伪彩/色斑**，观感反而变差。
3. **WB 前处理在最暗的场景（如 904 这类）仍可能偏差**，因为 RAW 亮部信号本身就接近噪声。
4. **两次训练约 4~5 小时**（L1 + L2，Sony+Canon 各一次）。

```
Step 1  L1 实现 + 快速校准（代码 + 1 epoch 冒烟）          ~20 min
   │    关键：200 iter 后打印 ccl/chroma/l1 各自量级，
   │          确认颜色项占 loss 的 3%~15%
   ▼
Step 2  L1 全量训练      Sony + Canon 各 50 epoch          ~2 h
   │    产出：两套 results.csv + 饱和度恢复率
   ▼
Step 3  判据评审
   │    ├─ 通过 → 做 L2
   │    └─ 失败 → 按下方判据表定位调整
   ▼
Step 4  L2 实现（AICM + IllumStatLoss + 复合选模）         ~15 min
   ▼
Step 5  L2 训练（先 Sony 验证，再 Canon）                  2.4 h
```

### 判据表（先定判据，再跑）

| 现象 | 处置 |
|---|---|
| PSNR 涨但饱和度 < 50% | `chroma_weight` 加倍（0.15→0.3），`ccl_lambda` 减半 |
| 饱和度涨但 PSNR 掉 | `chroma_weight` 减半；**检查 EvalDataset 是否漏改** |
| 两者都没动 | 检查 ISP 是否真的生效（打印增益值确认） |
| 出现伪彩色斑 | `chroma_weight` 降到 0.05，或改用不加权版本 |

### 为什么 L0 必须第一步

它是唯一「零训练就能拿到」的信息，直接决定 L1 值不值得做。跳过 L0 直接训练是最大的时间浪费。

### 为什么 L1 不拆成两次训练

ISP 单独做的颜色收益会被「选模仍看 PSNR」吃掉（最灰的 epoch 仍会胜出），拆开做会误导判断。

## 九、被否决的备选方案

| 备选 | 否决理由 |
|---|---|
| **用 GT sRGB 反推近似 RAW 当 gt_raw** | sRGB 端已夹紧 [0,1] + JPEG 有损，逆变换会放大量化误差与色块；等于用有损数据监督无损目标，噪声大于信号 |
| **照搬官方 AICM + L_icl** | L_icl 需要 gt_raw 做 Retinex 分解；本项目可算的只有 sRGB，光照图定义域不一致会失效 |
| **两阶段训练** | 官方 Stage2 是为冻结扩散模型设计的；UNet 不存在该约束，拆阶段只会让 L_ccl 生效的 epoch 减少 |
| **只用 L_ccl 不加 ChromaLoss** | 实测证伪：去饱和一半时 L_ccl 仅 −0.064，惩罚不足 |
| **打开 VGG 感知损失** | 对色偏敏感度低于宣传，且增加 ~1.5GB 显存与 30% 时长，性价比不如 ChromaLoss |
| **base_channels 32→48** | 8GB 逼近 OOM；且当前问题是输入/目标侧，不是容量 |
| **norm 改 batch** | batch=8 太小，BatchNorm 统计不稳定，且削弱逐图增益自适应 |

## 十、一页纸摘要

1. **v3 需修正**：官方消融证明颜色损失是三项齐涨，不是 trade-off。
2. **核心思路**：色彩工作前移到数据处理（WB），网络只专注亮度与去噪，损失只做兜底。
3. **WB 用 Gray World 而非 GT 反推**：实测 904 图 GT 反推撞上限失真，Gray World 稳定。
4. **L_ccl 必须改造 + 必须补 ChromaLoss**：实测纯 RGB 直方图 KL 对去饱和几乎无感。
5. **先做 L0**（10 分钟零训练），用饱和度恢复率决定是否投入。
6. **推荐做到 L2**：预期 PSNR +1.3~+2.7、SSIM +0.03~+0.06、LPIPS −0.08~−0.15、饱和度恢复 78%~92%。
7. **三条硬约束**：训练/评估/推理三处 ISP 同步改；加 nan 防护；所有产物 `_v4` 新目录。
