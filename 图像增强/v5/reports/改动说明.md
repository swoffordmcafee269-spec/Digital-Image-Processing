# v5 改动说明（相对 v1）

> 这份文档回答两个问题：**v5 具体改了哪几行、为什么这么改**。所有改动都在
> `v5/code/src/` 这份**副本**里，项目根的 `src/` 一个字节未动（`v5/run.py verify` 可证）。

---

## 一句话概括

v1 把 RAW 直接喂网络，通道响应差异（R≈0.5G）全靠网络隐式学；v5 在**数据层**显式做一次
Gray-World 白平衡，并在损失里加一条**只惩罚色差、不碰亮度**的色度项。

不改模型结构，不改参数量（16.93M），不改训练超参（除新增的色度权重）。

## 1. `src/data/wb.py`（新增，约 170 行）

**做什么**：输入 packed `(H,W,4)`，输出 `(gR, 1.0, gB)` 三个增益。

**五步**：

1. **去死黑 mask**：`sum(4ch) > 1e-4`。极暗图死黑像素占 8%~34%，不剔除会把中位数拉到 0 → 增益爆炸。
2. **剔高光**：按 99.5 分位截断。饱和像素会压低 R 的估计值，进而**高估** gR。
3. **gamma 域取中位数**：线性域动态范围太窄，gamma 域更稳。
4. **Gr/Gb 合并**：`gG = (gGr + gGb) / 2`，**不分开估**。分开估会让 G 通道产生棋盘纹。
5. **16×16 分块中位数**：块间取中位数，比全局均值抗「大面积单色区域」。

**增益裁剪** `[0.5, 4.0]`：L0 实测 1800 张全部落在区间内，裁剪只是安全兜底（实测触发率 2.2%/1.9%）。

### 性能：650 ms → 75 ms

第一版按块做 Python 双循环，1080×1920 有 **8039 个 tile**，单图 650 ms，全量要 20 分钟。
两处优化：

- **统计前 stride 抽稀**（步长 4）：270×480 仍有 13 万活像素，分位数/中位数估计误差 <1%，`partition` 开销降 16 倍
- **完全向量化**：`reshape(nby, tile, nbx, tile, 4)` 一次 `nanmedian(axis=(1,3))`

代价：`n_blocks` 从 8039 变成 8028（每块 64 个采样点而非 256），**增益数值与全量版一致**。

## 2. `src/data/dataset.py`

### 接入 WB

```python
gains = _wb_gains_for(self.cfg, packed, self._wb_cache, index)
if gains is not None:
    packed = apply_wb(packed, gains)
```

位置：`pack_raw` 之后、`random_crop_pair` 之前。**必须在 crop 之前** —— 否则每块 crop 会算出不同增益，同一张图前后不一致。

### 缓存路径解析（这里有个坑）

Dataset 的 `index` 是**相对自己的 filelist** 从 0 开始的。`train_ds` 和 `val_ds`
是两个不同的 filelist，如果共用一份缓存，索引必然错位。

所以 `data.wb_cache` 配**目录**，按 `<目录>/wb_gains_v5_<dataset>_<split>.npy` 自动拼，
`split` 取自 filelist 文件名。实测日志：

```
[WB] 命中 wb_gains_v5_sony_train.npy  (900 条)
[WB] 命中 wb_gains_v5_sony_val.npy    (100 条)
```

相对路径会依次尝试 cwd 和项目根两个基准，都命中不了就**回退实时计算**（不报错，只慢）。

## 4. `src/models/losses.py` — `chroma_loss`

**问题**：v1 用 `Charbonnier L1 (1.0) + SSIM (0.15)`。极暗图里亮度误差远大于色度误差，
梯度被亮度项拉走，**色彩恢复拿不到优化压力**。

**做法**：把 RGB 线性变换到「亮度 + 两条色差」：

```
Cb = B - Y,  Cr = R - Y,  Y = 0.299R + 0.587G + 0.114B
```

只在 `(Cb, Cr)` 上算 Charbonnier 距离。这是个线性可逆变换，梯度稳定，
且**对整体亮度偏移不敏感** —— 这正是「只管颜色、不管明暗」需要的性质。

冒烟里验证了三条性质：

| 检验 | 实测 |
|---|---|
| `pred == gt` | 1e-6（≈0） |
| 纯亮度偏移 `gt+0.1` | 1e-6（不惩罚） |
| 通道错乱 `RGB→BGR` | 0.338（惩罚足够大） |

第三条最关键：错乱时的惩罚是完美时的 **34 万倍**，说明这条损失确实盯着色度。

## 5. `src/train.py`

三处：

- `build_loss` 里按 `chroma_weight > 0` 追加色度项
- 日志列从 `[epoch, lr, train_loss, val_psnr]` 扩到 **+val_ssim**（val 只有 100 张，PSNR 的 SE 约 0.35 dB 不够显著，SSIM 更稳）
- `select_metric` 可切 psnr/ssim，默认 psnr（与 v1 保持一致便于对比）
- 路径按**项目根**解析，不受 cwd 影响

## 超参数变化

| 项 | v1 | v5 Sony | v5 Canon | 说明 |
|---|---|---|---|---|
| 模型 | 16.93M | 同 | 同 | 未改 |
| epoch | 50 | 50 | 50 | 同 |
| batch | 8 | 8 | 8 | 同 |
| patch | 512 | 512 | 512 | 同 |
| lr | 1e-4 | 1e-4 | 1e-4 | 同 |
| l1_weight | 1.0 | 1.0 | 1.0 | 同 |
| ssim_weight | 0.15 | 0.15 | 0.15 | 同 |
| **use_wb** | — | **true** | **true** | 新增 |
| **chroma_weight** | — | **0.10** | **0.12** | 新增 |

`chroma_weight` 为什么 Canon 高一点：Canon 的 gR 分布宽得多（p5=1.45 → p95=3.25，
Sony 是 0.72 → 2.56），场景光照变化更大 → 色度估计不确定性更高，需要更强约束。
